How to read this report

Accuracy. Recall@k is the fraction of relevant documents retrieved. Precision@k uses k as its denominator. MRR@5 uses the first relevant document. nDCG@k uses binary relevance and a log2 discount. Hit@k is 1 when any relevant document appears in the top k. Duplicate chunks from one document count once, at their first rank. A relevant document with many chunks can therefore lower precision@k.

Latency. p50/p95/p99 cover all queries. The first query is cold and is reported separately; indexing time includes cache lookup, embedding and index construction.

Balanced score. Accuracy, speed and cost are min–max normalized across the models in this run, then weighted 50/30/20. It is a decision aid, not an absolute score.

Cost. Token counts come from each model's own tokenizer where available. Cost is a hosted-API equivalent at the price configured for this run, not what the local model costs.
